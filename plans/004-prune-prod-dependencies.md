## Why this matters

`pnpm audit --prod` currently reports **2 high / 6 moderate / 1 low**
advisories — none of which ship to the browser. They come from build-time
tooling sitting in `dependencies`: the `shadcn` CLI drags in
`@modelcontextprotocol/sdk` → `hono` 4.12.23 (high: CORS credential
reflection — irrelevant, hono never runs here), and `@tailwindcss/vite` drags
in `vite`/`esbuild` advisories. This noise will bury a *real* advisory the day
one lands in an actual runtime dependency. Moving build-time packages to
`devDependencies` makes `pnpm audit --prod` a meaningful signal.

## Steps

### Step 1: Move the four build-time packages

In `frontend/package.json`, move these entries from `dependencies` to
`devDependencies`, keeping their exact version ranges:

- `shadcn` (build-time CSS import + component CLI)
- `tailwindcss`
- `@tailwindcss/vite`
- `tw-animate-css`

Leave in `dependencies`: `@fontsource-variable/inter` (font asset package —
also build-time in practice, but it contributes actual runtime assets to the
bundle; moving it buys nothing and muddies the semantic line), and everything
else currently there.

Keep both blocks alphabetically sorted (they are today).

**Verify**: `pnpm install` → exit 0 and `pnpm-lock.yaml` shows the packages
under dev importers (`git diff pnpm-lock.yaml` contains the moved entries).

### Step 2: Prove the build still works

**Verify**: `pnpm build` → exit 0. Confirm the CSS made it into the bundle:

```
grep -l "font-family" dist/assets/*.css
```

→ at least one match (Inter + Tailwind output present).

**Verify**: `pnpm test` → all pass. `pnpm typecheck` → exit 0.

### Step 3: Confirm the audit signal

**Verify**: `pnpm audit --prod` → reports **no high-severity advisories**, and
specifically no `hono`, `vite`, or `esbuild` entries. (If an unrelated *new*
advisory has been published against a true runtime dep since this plan was
written, note it in your report — do not fix it here.)

**Verify** (dev advisories still visible, as intended): `pnpm audit` (no
`--prod`) still lists the dev-chain advisories. That's expected and fine.

### Step 4: Sanity-check the Docker build (only if Docker is available)

```
docker build -t fitlytics-frontend-depcheck frontend/
```

→ exits 0. If Docker isn't available in your environment, state that in the
report; Step 2 already covers the same `pnpm install && pnpm build` path the
image runs.

## Maintenance notes
